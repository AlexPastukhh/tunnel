# План реализации и проверки

**Обновление после исторического хендоффа, 25.10.2026:** отдельным поручением пользователь разрешил разработку и установку зависимостей внутри Fortis Repo Docker. Исходники и тесты: [runtime/userscript-updater](../../runtime/userscript-updater/README.md); фактические проверки и остающиеся условия — [IMPLEMENTATION_LOG.md](IMPLEMENTATION_LOG.md). Это НЕ защищённая Windows-установка и НЕ перенос наружу. Фразы ниже «создаются только документы» отражают предыдущий момент подготовки плана.

Статус на 25.10.2026: документация подготовлена; код updater и анализаторы не установлены. Источник требований — [REQUIREMENTS.md](REQUIREMENTS.md). Этапы ниже — работа следующего чата, не отчёт о выполнении.

## Целевая операция пользователя

Открыть лёгкую доверенную оболочку → выбрать сохранённую пару → нажать «Проверить» → посмотреть отчёт и изменения → отдельно нажать «Обновить» и подтвердить замену в этом же окне → обновить нужные вкладки и проверить фактическую версию. Завершение анализа само по себе не инициирует установку. Список пар и политика сохраняются вне области записи агента.

## P-01. Уточнить фактические входы без лишнего доступа

- Прочитать AGENTS и этот пакет, проверить status/index и сохранить чужую работу.
- Выбрать первым поддерживаемым скриптом Notifier. Helper поддерживать как отдельную пару/политику; не включать его незакоммиченные изменения в работу попутно.
- Для исходников использовать подтверждённый корень `C:\Users\alexa\Repos`, а не устаревший `C:\134` из connector metadata.
- Получить от пользователя только metadata его Loader, когда это действительно потребуется для перенастройки. Не читать профиль/базу расширения и секретные GM-данные через обходной маршрут.
- Подготовить точные owner-команды для проверки/создания защищённой установки. Агент их на Windows не исполняет.

Готовность: зафиксированы реальные source/target и путь первоначальной установки; нет притворного подтверждения текущих ACL/Loader.

## P-02. Спроектировать небольшой доверенный компонент

- Отдельно model/backend и GUI, чтобы действия с файлами/проверками тестировались без запуска owner GUI.
- Переиспользовать ESLint/Semgrep CLI и их структурированные отчёты; оболочка отвечает за пары, запуск, показ результатов и продвижение одобренных байтов. Не создавать собственный анализатор, обязательный сервер или тяжёлую платформу.
- Явные форматы настроек пар, политики анализаторов, snapshot/review и истории установки с версиями схем.
- Настройки/инструменты/модули доверенного компонента загружаются только из защищённой установки. Исключить импорт Python/Node/ESLint-конфигов из текущего каталога Repo и произвольные shell-команды из кандидата.
- При файловой работе проверять путь, ссылки/перенаправления и допустимую область; не превращать picker в unrestricted owner file-write API агента.
- Выбрать Python/Tkinter либо PowerShell/WinForms по реальной доступности Windows; оба пока только кандидаты. Доступность обычного Windows Python подтверждена прежним запуском helper, наличие GUI-библиотеки — нет.

Готовность: исходники подготовлены в Git, действие не меняет live userscript. Первоначальное размещение доверенного компонента само требует ручной проверки и закреплённых хешей.

## P-03. Зарегистрированные пары и единое окно

- Список пар с понятным именем; добавить/изменить/удалить, выбрать последнюю.
- Source picker и target picker; поддержать создание нового target. Отмена выбора не сохраняет частично заполненную пару.
- До сохранения отсеивать одинаковые source/target и конфликтующие назначения. Ошибка чтения настроек не должна приводить к тихому сбросу/перезаписи.
- Основные действия — **две отдельные кнопки «Проверить» и «Обновить»**; дополнительные — «Результаты/изменения» и «Откат». Совмещённая кнопка запрещена последним уточнением пользователя.
- «Проверить» только запускает анализ и показывает результат; никакой записи target или автоматического запроса установки после PASS. «Обновить» доступна только для действительного успешного результата этой пары/snapshot. Смена пары, состава, политики или существенное изменение исходника/target снимает допуск и требует отдельного повторного нажатия «Проверить»; не запускать скрытый combined flow.
- Показ статуса/ошибок рядом с выбранной парой; фоновые проверки не должны бесконтрольно блокировать GUI. Подтверждение привязано к текущей паре и snapshot, а не к устаревшему callback.

Готовность: пользователь не вводит пути при каждом обновлении, анализ и установка доступны из одного доверенного окна.

## P-04. Неизменяемая копия и содержательный просмотр

- Снять bytes snapshot кандидата в защищённое review-хранилище, вычислить SHA-256; не исполнять JavaScript.
- Проверить userscript header и показать различия с установленным файлом: версии, идентичность, размер, хеши, diff, разрешения, новые ресурсы/адреса. Сам header подгружаемого JS не изменяет grants установленного Loader.
- Проверять фактически устанавливаемый bundle и весь разрешённый исполняемый состав. Анализ одного src без проверки итоговой сборки недостаточен.
- Идентифицировать текущий target и его hash до подтверждения. Если он изменился, потребовать новый просмотр; недавний PASS не относится автоматически к изменившимся байтам/политике.

Готовность: понятен точный набор проверяемых и устанавливаемых данных; Repo больше не может подменить их после просмотра.

## P-05. Подключить обязательный анализ

- Закреплённые ESLint и Semgrep CE плюс доверенные правила; не ставить зависимости из package.json проверяемого скрипта с owner-правами.
- ESLint: явный доверенный config, запрет config lookup и inline отключений; не выполнять autofix при проверке.
- Semgrep: явные локальные правила, запрет nosem-подавлений, намеренно заданные failure flags. `semgrep scan` по умолчанию может вернуть 0 при находках: нельзя считать один exit 0 достаточным.
- Весь устанавливаемый состав обязан быть проверен: ignore-файлы, лимиты размера, parsing errors и timeouts не должны незаметно уменьшить покрытие. Проверять и коды завершения, и структурированный результат.
- Никакой автоматической отправки исходников/GM-данных в облако. Sonar/GitHub CI можно предложить отдельно, но они не заменяют обязательный локальный допуск.
- Добавить политику по risky API/динамическому коду/сети/файлам/GM и тесты нужных ограничений Send. Конкретные исключения документировать; не выдавать полноту regex-поиска за доказательство безопасности произвольного JavaScript.
- Показывать статусы: не настроено / выполняется / ошибка / находки / неполное покрытие / пройдено. Пользователь читает результаты в этом же окне.

Готовность: обычная установка недоступна, если обязательная проверка не завершена успешно. Нет скрытого `--force`, ручного обхода или доверия отчёту, переданному агентом.

## P-06. Подтверждение, продвижение и откат

- В том же окне запросить явное подтверждение с парой, source/target, версией, хешем, статусом проверок и адресом backup.
- Сохранить прежние байты/metadata вне контроля агента, повторно проверить пути/target, выполнить замену проверенным snapshot без перекодирования, подтвердить readback.
- Использовать подходящую атомарную замену в одном томе и корректно обработать занятость/отказ доступа. Не сообщать успех по факту начала копирования.
- Повторный клик/callback не должен создавать вторую незапланированную операцию. Хранить минимальный журнал и точный rollback reference.
- Откат — отдельное подтверждаемое действие через доверенный инструмент; применять ранее сохранённые байты и проверять итоговый хеш.

Готовность: U-01, U-07 и C-02/C-08–C-10 подтверждены тестами, прежде чем предложить owner-установку.

## P-07. Ручная установка и первоначальное переключение Loader

- Подготовить reviewable пакет, hashes, точные owner-инструкции, отрицательные тесты и откат; только затем передать пользователю.
- Пользователь обычной owner-учёткой размещает доверенную часть вне RW-mounts с проверенными правами. Не запускать доверенный updater постоянно из Repo.
- Сохранить старый Loader/target и явно перенаправить существующий Loader на Approved-файл. @name/@namespace, GM storage и другие userscripts не сбрасывать.
- При уже существующем SRI не молча удалять его: объяснить выбранную модель, подтвердить owner-решение и проверить enforce/несовпадение хеша в установленной версии Tampermonkey.
- Проверить подхват после обновления страницы и фактическую версию во всех нужных браузерных профилях, учитывая кэш @require. Не заявлять мгновенный reload заранее.

Готовность: фактический owner-result/sha и browser smoke зафиксированы отдельно от synthetic/Docker проверок. До этого состояние SOURCE/PREPARED, не DEPLOYED.

## P-08. Матрица приёмки

| Проверка | Ожидаемый исход |
|---|---|
| Перезапуск updater после регистрации нескольких пар | Пары/пути/кириллица/выбор сохранены; нет скрытой установки |
| Нажатие «Проверить», включая завершение с PASS | Target не изменён; установка ждёт отдельного нажатия «Обновить» |
| Отмена picker, анализа или подтверждения | Target не изменён, настройки не испорчены |
| Source совпадает с target, конфликт пары, ссылка/reparse/hardlink | Понятный отказ до записи |
| Source изменён после snapshot/PASS | Кнопка «Обновить» блокируется; требуется отдельная повторная проверка изменившегося кандидата |
| Target изменён после просмотра | Установка останавливается и требует новый review |
| Запрещённый безопасный тестовый пример, nosem/eslint-disable/ignore попытка | Находка/отказ, обычная установка недоступна |
| Анализатор отсутствует, завис, упал или пропустил файл | Не PASS; target прежний |
| Потеря доступа, занятый target, ошибка записи/журнала | Ясный исход и восстановимая резервная копия; нет фиктивного успеха |
| Успешное подтверждение | Установлены ровно показанные bytes, hash совпадает, backup доступен |
| Откат | Прежний hash восстановлен без удаления других версий/GM-данных |
| Попытка записи из выданной агенту среды в тестовый marker защищённого каталога | Отказ; реальная граница подтверждена только по этому проверенному маршруту |
| Изменение Repo без подтверждения | Действующая копия/браузерная версия остаются прежними |

Linux unit/fixture-тесты покрывают модель, обработку результатов и временные файлы. Они не заменяют Windows ACL/GUI, Tampermonkey cache и owner acceptance. Тестовые snippets не запускать на реальных данных пользователя и не делать настоящий ChatGPT Send ради updater.

## Первичные справочники

- [ESLint CLI](https://eslint.org/docs/latest/use/command-line-interface): --no-config-lookup, --config, --no-inline-config.
- [Semgrep: собственные правила](https://docs.semgrep.dev/writing-rules/overview), [локальный запуск](https://docs.semgrep.dev/running-rules), [CLI/exit codes](https://docs.semgrep.dev/cli-reference).
- [Tampermonkey @require](https://www.tampermonkey.net/documentation.php?locale=en&q=externals), [SRI](https://www.tampermonkey.net/documentation.php?locale=en&q=sri), [grants](https://www.tampermonkey.net/documentation.php?locale=en&q=grant).
- [Docker bind mounts](https://docs.docker.com/engine/storage/bind-mounts/). Отдельный checker не изолирован от агента, если агент может управлять Docker daemon/его образом/контейнером.

Доступность платформ, версии инструментов и фактические флаги сверять с текущей официальной документацией перед установкой. Не переносить старое ограничение «Semgrep обязательно требует WSL на Windows» без проверки: текущая первичная страница производителя уже упоминала native Windows support; это не проверка установленного инструмента пользователя.
