Helper выполнен пользователем в Windows PowerShell. По предоставленному выводу `--check` нашёл единственный чат «Тест связи»; обычный запуск подключил сессию и получил `pending` → `claimed` → `send_initiated`. Это реальная проверка owner-local API по выводу пользователя, а не выполненная агентом автоматизация Windows.

`SEND_ATTEMPT_REPORTED=True`, `DELIVERY_CONFIRMED=False`. Успешная файловая доставка и завершение теста не подтверждены. Точные установленные версии Windows Viewer/Notifier по SHA не сверены.

Факт попытки для корреляции с локальным журналом:

- `task_2b5017a10bc04084ac545043bc37899c`.

## Назначение и запуск

[Run-ObservatorySessionTest.py](Run-ObservatorySessionTest.py) — ограниченный тест для единственного адресата «Тест связи» и оригинала «Тест». Это не общий CLI/MCP. Windows checkout подтверждён пользователем: `C:\Users\alexa\Repos`; metadata connector с другим hostPath не использовать вместо этого пути.

Только чтение, без connect/Send и записи operation journal:

```powershell
$testScript = 'C:\Users\alexa\Repos\tunnel\observatory\v1\candidates\direct-api-test-20261024\Run-ObservatorySessionTest.py'
py -3 $testScript --check
```

Запуск без аргументов предназначен для одной попытки connect/Send. Предыдущая попытка уже состоялась: повторный запуск должен только наблюдать её, а не отправлять заново. Не удалять защитный journal ради обхода этой проверки. Неизвестные аргументы отвергаются до авторизации.

## Авторизация, семантика и защита от повтора

Владелец запускает helper обычным Windows Python при работающем Viewer в owner-launch и открытой целевой вкладке с Notifier. Используется owner-private launcher текущего процесса и установленный owner/SID/ACL validator. Bearer не выводится в stdout/argv/журнал и не передаётся в Repo. Viewer/службы, API, права и ключи helper не меняет.

Выбор цели идёт по точному нормализованному названию с проверкой единственного chat/client; при неоднозначности, архивировании или незавершённой команде отправка запрещена. `--check` печатает только разрешённые title/chat/session/client-count/age и per-route timings. Названия из свежего discovery имеют приоритет над архивным fallback.

Helper запрашивает `mode=send`: текущие Notifier 5.7.33/5.7.34 выполняют File + Send с проверкой вложения, а старые версии могли отправлять короткий исходник обычным текстом. Согласование runtime capabilities протоколом не реализовано. Перед новым отдельно согласованным тестом нужно проверить версию целевого профиля и сначала карточку вложения без Send.

Защитный owner-private `direct-api-test-*.json` записывается до dispatch POST и блокирует повтор также при потерянном ответе. Helper не восстанавливает архивные сессии, не угадывает клиента и не повторяет неясный результат. `send_initiated` означает ACK о попытке, не receipt ChatGPT.

## Воспроизводимая проверка исходника

10 синтетических flow/CLI тестов: отказ при неоднозначности/архивировании/in-flight, read-only CLI, один connect/Send, использование существующей привязки, запрет повтора после потерянного ответа. Проверка из этого каталога: `python3 -m unittest -q test_session_test.py`. Эти тесты не проверяют Windows ACL/Edge или реальный Send.
