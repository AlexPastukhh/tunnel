# Работа с этим репозиторием

Начать с [README](README.md), [навигации](docs/README.md) и текущего STATE/plan выбранной задачи. Архитектуру и историю читать по необходимости. Исторические документы не использовать как текущую конфигурацию; Markdown не заменяет live-проверку.

- Выполнять задачу пользователя. Не трактовать подключение MCP-плагина как запрос создать сайт.
- Различать native HOST, native Repo Docker и два Site MCP endpoint. Диагностика одного не доказывает состояние другого.
- HOST: только разрешённые файловые/терминальные действия. Автоматизация основного Windows GUI, screenshots и ввод не разрешены.
- Repo Docker: рабочие файлы и результаты сохранять в `/workspace/repo/Workfiles` — внутреннем Docker volume. Прежнюю Windows Workfiles не использовать и не удалять. До отдельной смены mounts старые binds остаются доступом к Windows; `/workspace/repos` пока тоже может изменять Windows-файлы.
- Не публиковать ключи, профили с секретами, логи с payload, snapshots ZIP или приватные upstream URL. Не расширять аудиторию Site или экспорт Bridge попутно.
- После timeout мутации сначала проверить состояние. Не повторять вслепую.
- Не удалять/чинить metadata Windows linked worktrees из Linux только из-за недоступных Windows-путей.
- При изменении runtime/tool presentation обновить владельца фактов; INSTRUCTIONS/OPERATIONS менять при изменении процедуры доставки/эксплуатации. Не дописывать в общие инструкции релизный журнал. Отмечать только реально выполненные deploy/restart/проверки.
- Для Observatory читать [текущий README V1](observatory/v1/README.md). После изменения поддерживать там source/версию, установленное состояние, проверки и открытые вопросы отдельно; в общих docs оставлять ссылки. Исторические candidate-статусы не считать реестром текущей установки.
- runtime/ — исходники-копии. Для применения нужен явный перенос в действующую установку и проверка. Site исходники принадлежат отдельному Sites Git, не этому репозиторию.

## Общий workflow агентов и документация

- Обязателен единый [протокол ведения документации: владельцы фактов, DRY/KISS/YAGNI, evidence и Git](docs/agent-workflow/README.md). После значимого шага поддерживать изменившиеся факты и следующие действия в том же шаге; историю писать кратко в журнал соответствующей работы. Не размножать текущие статусы по сводкам.
- Для Repo/Tunnel перед работой читать [security-реестр](docs/agent-workflow/TUNNEL_SECURITY_ISOLATION.md), [STATE](docs/agent-workflow/STATE.md) и необходимые последние [JOURNAL](docs/agent-workflow/JOURNAL.md). Проверять влияние шага на все три роли; менять только затронутые записи, без обязательной перезаписи неизменившихся страниц.
- Пользователь поручил осмысленные локальные коммиты только своих документов/изменений после проверки diff и индекса. Push и применение runtime — отдельные действия; незавершённую работу других чатов сохранять.
- Изменения Windows-хоста и пользовательских профилей готовить как конкретные команды с проверкой/откатом для ручного исполнения пользователем. Проектные действия внутри уже разрешённой среды выполнять в её пределах.
